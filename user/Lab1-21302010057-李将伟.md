## 1.2. pingpong
### 1.2.1 实验步骤
a. 创建user/pingpong.c文件，实现父子进程通信：使用两个管道，父进程写PID，子进程读并写回PID，打印指定消息。代码如下：
   ```c
   #include "kernel/types.h"
   #include "kernel/stat.h"
   #include "user/user.h"

   int main(int argc, char *argv[]) {
       int f2c[2], c2f[2];
       pipe(f2c);
       pipe(c2f);
       
       if (fork() == 0) {
           // 子进程
           close(f2c[1]); // 关闭父写端
           close(c2f[0]); // 关闭子读端
           int father_pid;
           read(f2c[0], &father_pid, sizeof(int));
           printf("%d: received ping from pid %d\n", getpid(), father_pid);
           int child_pid = getpid();
           write(c2f[1], &child_pid, sizeof(int));
           close(f2c[0]);
           close(c2f[1]);
       } else {
           // 父进程
           close(f2c[0]); // 关闭父读端
           close(c2f[1]); // 关闭子写端
           int father_pid = getpid();
           write(f2c[1], &father_pid, sizeof(int));
           int child_pid;
           read(c2f[0], &child_pid, sizeof(int));
           printf("%d: received pong from pid %d\n", getpid(), child_pid);
           close(f2c[1]);
           close(c2f[0]);
       }
       exit(0);
   }
   ```
b. 在Makefile中添加编译任务：插入`$U/_pingpong\`。
c. 编译并测试：运行make qemu-gdb，观察父子进程打印消息。

### 1.2.2 实验测试结果
测试通过，输出类似"4: received ping from pid 3" 和 "3: received pong from pid 4"。截图：（显示正确输出）

## 1.3. find
### 1.3.1 实验步骤
a. 创建user/find.c文件，实现递归查找：遍历目录树，匹配文件名或目录名，输出相对路径。代码如下：
   ```c
   #include "kernel/types.h"
   #include "kernel/stat.h"
   #include "user/user.h"
   #include "kernel/fs.h"

   void find(char *path, char *name) {
       char buf[512], *p;
       int fd;
       struct dirent de;
       struct stat st;
       
       if ((fd = open(path, 0)) < 0) {
           fprintf(2, "find: cannot open %s\n", path);
           return;
       }
       
       if (fstat(fd, &st) < 0) {
           fprintf(2, "find: cannot stat %s\n", path);
           close(fd);
           return;
       }
       
       switch (st.type) {
       case T_FILE:
           if (strcmp(name, path) == 0) {
               printf("%s\n", path);
           }
           break;
       case T_DIR:
           if (strlen(path) + 1 + DIRSIZ + 1 > sizeof buf) {
               printf("find: path too long\n");
               break;
           }
           strcpy(buf, path);
           p = buf + strlen(buf);
           *p++ = '/';
           while (read(fd, &de, sizeof(de)) == sizeof(de)) {
               if (de.inum == 0)
                   continue;
               memmove(p, de.name, DIRSIZ);
               p[DIRSIZ] = 0;
               if (stat(buf, &st) < 0) {
                   printf("find: cannot stat %s\n", buf);
                   continue;
               }
               if (strcmp(de.name, ".") != 0 && strcmp(de.name, "..") != 0) {
                   if (strcmp(de.name, name) == 0) {
                       printf("%s\n", buf);
                   }
                   if (st.type == T_DIR) {
                       find(buf, name);
                   }
               }
           }
           break;
       }
       close(fd);
   }

   int main(int argc, char *argv[]) {
       if (argc != 3) {
           fprintf(2, "Usage: find <path> <name>\n");
           exit(1);
       }
       find(argv[1], argv[2]);
       exit(0);
   }
   ```
b. 在Makefile中添加编译任务：插入`$U/_find\`。
c. 编译并测试：运行make qemu-gdb，执行find . filename，观察输出路径。

测试通过，正确输出匹配的文件/目录路径，包括递归查找。截图：（显示./BY4TJCrL 和递归路径）

# 二、问题解答
## 2.1 问题1内容
在pingpong实验中，使用pipe()创建两个管道f2c和c2f。fork()后，父进程写f2c，子进程读f2c并写c2f，父进程读c2f，实现PID传输。不能只用一个管道，因为单管道无法实现双向通信；多个来回需要两个管道，否则会死锁。

## 2.2 问题2内容
提前关闭不使用的一端以避免阻塞：管道读端在写端关闭且缓冲区空时返回0，写端在读端关闭时收到SIGPIPE。关闭不使用端确保正确阻塞和EOF检测。

## 2.3 问题3内容
如果子进程不关闭管道写端，wc可能不会终止，因为管道写端仍打开，read不会返回EOF，导致wc等待更多输入。

## 2.4 问题4内容
如果没有exit(0)，父进程可能继续执行shell代码，导致未定义行为，因为程序未显式退出。
